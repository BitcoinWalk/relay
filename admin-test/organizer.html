Organizer permissions: staging test

Run after the organizer-mode upgrade. Use your normal browser with a Nostr extension. Switch the selected identity in the extension between steps.

This creates a public, unapproved test proposal on staging. It is not a calendar event and will not be automatically deleted. Your public test data is saved in this browser so you can continue between identity changes. No private keys are stored.

1. Organizer submits

Select a separate organizer identity—not the BitcoinWalk super-admin.

2. Admin authorizes

Switch to the BitcoinWalk super-admin. This grants the test creator permission to edit this test city only. It does not approve the walk.

3. Organizer edits

Switch back to the same organizer identity.

The extension will be asked to sign an edit and an approval attempt. The relay must reject the approval attempt.

Second-editor tests

If steps 1–3 passed, continue here in the same browser. Do not repeat the earlier steps. These tests add a second public, unapproved test city controlled only by the admin, to check cross-city isolation. Neither test city expires automatically.

4. Choose the second editor

Select a third Nostr identity, different from the creator and super-admin. This reads its public key only.

5. Admin grants access

Switch to the super-admin. This creates the protected test city and adds the second editor to the original test city only. Other editors are preserved; no walk is approved.

6. Second editor tests access

Switch to the second editor. Approve signing an edit to each test city. Only the assigned-city edit should be accepted.

7. Admin revokes access

Switch to the super-admin. Remove only this second editor from the original test city. The creator keeps access.

8. Revoked editor retries

Switch back to the second editor. Approve signing a new edit; it must be rejected.

Ready. If the organizer workflow passed, continue at step 4 in the same browser.
